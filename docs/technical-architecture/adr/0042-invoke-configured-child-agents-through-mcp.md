# Invoke configured child Agents through an internal MCP tool

Each callable child Agent Definition generates one internal MCP tool with a definition-specific description, bounded business input, and exact result contract. A parent discovers only the generated children in its pinned Definition allowlist and cannot submit an arbitrary Definition identity. All generated tools share a thin adapter over Nano's existing Delegation Kernel and PostgreSQL runtime; child Agents are not separate MCP Servers.

Definition identity and integer version form the exact `identity@version` reference. Tool names are derived, not authored: `delegate.<identity>.v<version>`. Startup validates MCP name and length constraints, rejects collisions, verifies the child's task and result contracts, and confirms that both the parent and child Executors permit the relationship. Configuration can narrow those registered ceilings but cannot create authority.

Sprint 10 retains the existing depth-one topology: one parent may create one child in total, the child cannot delegate, and there is no sibling, fan-out, recursion, join, quorum, or free-form Agent conversation. This ADR standardizes how a configured child is invoked; it does not widen the graph.

Delegation targets the `io.modelcontextprotocol/tasks` extension defined by SEP-2663 for protocol version 2026-07-28, not the incompatible experimental Tasks API in the 2025-11-25 core specification. After per-request capability negotiation, one PostgreSQL transaction creates the Delegation, child Agent Run and Job, binds the stable `action_id`, and moves the parent to `waiting` without a Lease before `tools/call` returns a Task projection. `task_id` equals `delegation_id`; `tasks/get` projects durable child state and terminal result/error, while `tasks/cancel` maps to bounded Kernel cancellation. Nano implements protocol-compatible `tasks/update` handling but never emits `input_required`; there is no second Task table, Task-list API, or `tasks/result` method.

Child terminalization requeues an eligible parent through PostgreSQL. The resumed parent resolves `tasks/get` once and appends the validated Agent Result reference as the original Action Result. It never retains a Lease or polls MCP while waiting. Notifications are advisory; normal Job polling recovers a missed notification.

A successful child stores one immutable, contract-versioned Agent Result with canonical JSON, SHA-256, and byte size. Delegation, Task projection, parent Checkpoint, and Trace carry only its reference and integrity metadata. The child receives a bounded server-built context manifest; full parent context, hidden reasoning, raw Provider envelopes, and model-supplied authority never cross the boundary.

The first deployment keeps MCP Host and Nano Tools MCP Server in the Worker process over an official-SDK in-memory transport. Configured delegation is gated on a selected official SDK version and Go toolchain passing Nano conformance tests for the locked protocol, capability negotiation, polymorphic `tools/call`, `tasks/get`, `tasks/update`, and `tasks/cancel`. If first-class extension helpers are absent, a narrow adapter may use the SDK's official custom-method surface with exact SEP-2663 schemas; it may not invent or vary the wire contract. Production release should prefer the stable SDK release when available. Remote transport remains deferred until another real Host requires it.

We rejected direct child-Run creation in individual Executors because it hard-codes Agent identities and duplicates durable lifecycle behavior. We also rejected one MCP Server per Agent and MCP Sampling because both introduce a second orchestration authority without improving the bounded runtime.

Implementation note (2026-07-28): official Go SDK `v1.7.0-pre.3` provides the locked protocol, in-memory transport, request extensions, and custom methods, but its public `tools/call` result cannot encode the SEP-2663 Task variant and a known method cannot be replaced with a custom codec. No newer published prerelease exists, official `main` commit `bc72835f62eb` retains the same public boundary, and maintainer-authored [Go SDK issue #942](https://github.com/modelcontextprotocol/go-sdk/issues/942) explicitly records that Tasks have not been implemented. The configured-child adapter therefore remains disabled. Nano records no private Task wire format and keeps the rest of the framework active under the explicit Sprint 10 gate.
